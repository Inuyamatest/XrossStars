## 2. ラウンド

### 2-1. ラウンドの勝利条件

- ✅ 「対戦相手のリーダーを全員ダウンさせたら、ラウンド勝利です。どちらかのプレイヤーのリーダーが全員ダウンしたとき、ラウンドは終了し、新しいラウンドが始まります。」（p.11）

### 2-2. ラウンド終了時の処理

- ✅ ラウンド終了時、以下の順で処理する（p.11）：
  1. プレイエリアのカードを裏向きにトラッシュに置く。ただしタクティクスカードは表向きのままトラッシュに置く
  2. 手札をすべて裏向きにトラッシュに置く
  3. すべてのダメージカウンターを取り除く
  4. ダウンしているリーダーを全員復活させる（縦向きに戻す）
- ✅ 「覚醒しているリーダーは覚醒したままにし、装備を付けたままにします。」「トラッシュはそのままにし、デッキのシャッフルも行いません。」（p.11）＝覚醒状態・装備・トラッシュの内容・デッキの中身/順序はラウンドをまたいで持ち越される

### 2-3. 次ラウンドの準備

- ✅ 以下の順で行う（p.11）：
  1. 両プレイヤーは自分のタクティクスデッキからカードを1枚選び、タクティクスエリアに裏向きに置く（※タクティクスデッキにカードが1枚もなければ何もしない）
  2. プレイポイントカードを1枚追加する（2ラウンド目は1ターンに使えるPPが4、3ラウンド目は5になる）
  3. 両プレイヤーはデッキから4枚カードを引き、直前のラウンドに負けたプレイヤーからターンを始める（＝直前のラウンドの敗者が次ラウンドの先攻になる）

### 公式根拠（2章共通）
- Playing Manual p.11「ラウンドの終了」「次のラウンドの準備」

## 3. リーダー4枚の状態

### 3-1. 基本構造

- ✅ リーダーカードは4枚選んでチームを作る（p.02）
- ✅ リーダーカードには「覚醒前」「覚醒後」の2つの状態があり、覚醒後はカードを裏返して表にする（＝物理的に1枚のカードの裏表で覚醒前後を表現、片面ずつ異なる体力・攻撃力・効果を持つ）（p.02, p.08）
- ✅ カード記載項目：カードタイプ、覚醒アイコン（覚醒後のみ）、カードの効果（覚醒時効果）、カード名、タグ、体力、攻撃力（p.02）

### 3-2. ダウン

- ✅ 「体力以上のダメージを受けたリーダーは、ダウンします。」（p.08）
- ✅ ダウン時処理：「リーダーの上のダメージカウンターをすべて取り除き、リーダーを横向きにします。」（p.08）
- ✅ ダウン中のリーダーは：アタッカーになれない／アタックやカード効果の対象にできない／ダメージを受けることもない（p.08）

### 3-3. 覚醒

- ✅ 覚醒条件：「アタックによって対戦相手のリーダーをダウンさせたとき、アタッカーを覚醒させます。」「『アタック後』効果でダウンさせたときも覚醒させます。」（p.08、およびFAQ Q2 p.14「アタック後効果でダウンさせても覚醒する」）
- ✅ 覚醒処理：リーダーを裏返し覚醒後面を表にし、「覚醒時」効果を実行する（p.08）
- ✅ 相手の最後のリーダーを倒した場合も覚醒し、「覚醒時」「アタック後」効果も実行する（p.15 FAQ Q4）
- ⚠️ 要確認: 「すでに覚醒しているリーダーが再度ダウンを取っても再覚醒しない」という趣旨は、マニュアル本文に明示の一文としては見当たらない。ただしリーダーは覚醒前後で1枚の裏表しかなく、「覚醒したとき」に効果が発動する構造（p.08）である以上、既に覚醒済み＝すでに覚醒後の面が表になっている状態からは「覚醒する」という状態遷移自体が起こり得ないと解釈するのが自然。この解釈は🧩実装上の仮仕様として明記した上で採用し、公式に明言された確定事項とは区別する

### 3-4. 装備カードとの関係

- ✅ タクティクスカードの一部（サブタイプ「装備」）はリーダーに装備でき、装備している間効果が働く（p.10、本書「16. タクティクスカード」参照）
- ✅ ダウンしたリーダーが装備しているカードの扱いの一例：タクティクスカード「復活ポータル」は「ダウンしている自分のリーダー1体を、ダウンしていない状態に戻す。そのリーダーが装備しているカードすべてを表向きにトラッシュに置く。」という効果を持つ（p.17 FAQ Q10の例示カード）。これは個別カードの効果例であり、ダウン時に装備カードが自動的にどうなるかという一般ルールではない
- ⏳ リーダーがダウンした瞬間に装備カードが自動的にトラッシュされる等の一般ルールがあるかどうかは、上記の個別カード例以外には明記が見当たらず不明

### 3-5. リーダーが場から離れる場合

- ⏳ リーダーが4枚以外の状態になる（追加/除外される）ケースについての一般ルールは、確認した範囲では見当たらない

### 公式根拠（3章共通）
- Playing Manual p.02, p.08, p.10, p.14, p.15, p.17

## 4. セットアップ（試合の準備）

- ✅ 以下の順で行う（p.05）：
  1. リーダーカード4枚を覚醒前が表になるように置く
  2. タクティクスデッキ（5枚）を裏向きに置く（※自分の裏向きのタクティクスデッキはいつでも自分で見られる）
  3. デッキをシャッフルし、裏向きに置く
  4. プレイポイントカードを3枚置く
  5. ジャンケンをして1ラウンド目の先攻プレイヤーを決める。勝った方が先攻/後攻を選べる
  6. 両プレイヤーは自分のタクティクスデッキから1枚選び、裏向きのままタクティクスエリアに置く
  7. 後攻プレイヤーはさらに「PPチケット」カードを表向きにタクティクスエリアへ置く（PPチケットは後攻プレイヤーが使える特殊なタクティクスカード）
  8. 両プレイヤーはデッキから4枚引き、手札にする
  9. 最初のラウンドが始まり、先攻プレイヤーからターンを始める

### 先攻・後攻による違い（明確化）

- ✅ 先攻/後攻はジャンケンで決定（1ラウンド目のみ。2ラウンド目以降は前ラウンドの敗者が先攻、p.11）
- ✅ 後攻プレイヤーのみ、タクティクスエリアにPPチケットを追加で置く（先攻は置かない）
- ✅ 先攻・後攻とも初期手札は4枚で同数（p.05）
- ✅ 「先攻のプレイヤーは、1ターン目の始めにカードを引く？」→「引きます。」（p.17 FAQ Q13）＝先攻1ターン目の開始フェイズにもドローの例外はない
- ✅ 先攻1ターン目のみの制約：タクティクスカードをプレイできない（p.06, p.10。本書「9. メインフェイズ」参照）
- ✅ マリガン（引き直し）は存在しない（p.17 FAQ Q14）

### 公式根拠
- Playing Manual p.05「試合の準備」、p.17 FAQ Q13/Q14

## 7. メインフェイズ

- ✅ 自分のターンのメインフェイズでは、以下の行動を好きな順番で行える（p.06）：
  - 手札のアタックカードをプレイする
  - 手札のメモリアカードをプレイする
  - タクティクスエリアのカードをプレイする（※1ターンに1枚まで。先攻1ターン目はプレイできない）
- ✅ カードをプレイするときはコストと同じ数のPPを支払う（横向きのPPカードを1枚縦向きから横向きにする＝支払い）（p.06）
- ✅ 「アタックカードをプレイすれば、同じリーダーで何回アタックしても構いません。」（p.07）＝1ターン中・1リーダーあたりのアタック回数に公式ルール上の上限はない（手札のアタックカード枚数とPPが続く限り、同じリーダーで何度でも攻撃できる）
- 🧩 上記より「メインフェイズで行える行動の回数」は、アタックカード／メモリアカードはPPと手札が続く限り実質無制限、タクティクスカードは1ターン1枚、という理解でよい（各行動の回数上限そのものは明記された数値としてではなく、上記のような構造から導かれる）

### 公式根拠
- Playing Manual p.06「ターンの進め方」、p.07「アタックカードのプレイ」

## 8. 終了フェイズ

## 9. PP（プレイポイント）

- ✅ 遊ぶために必要なアイテムとして「プレイポイントカード5枚」が挙げられている（p.03）
- ✅ ラウンドごとの上限：1ラウンド目は3PP、2ラウンド目は4PP、3ラウンド目は5PP（p.04の配置図、p.05セットアップ④「プレイポイントカードを3枚置く」、p.11「プレイポイントカードを1枚追加」）
- ✅ PPの表現：縦向き＝未使用（支払い可能）、横向き＝支払い済み（p.06の図解「プレイポイントカードを1枚横向きにすることで、プレイポイント（PP）を1支払うことができます」）
- ✅ 開始フェイズにPPをすべて回復（横向き→縦向き）する（p.06）
- ✅ ラウンド間で「プレイポイントカードを1枚追加」する形で上限が増える。既存のPPカードの向き自体は、次ラウンド開始時の開始フェイズで通常通り全回復される（ラウンド終了時のリセット処理④点にPPカードのリセットは明記されていないが、次ラウンド最初のターンの開始フェイズで①「PPをすべて回復」が通常通り実行されるため、結果的に全回復される）
- ✅ 回復（PPに限らず）の定義：「PPの回復とは、横向きのプレイポイントカードを縦向きにすることです。横向きのプレイポイントカードより多くPPを回復するときは、横向きのプレイポイントカードをすべて縦向きにします。」（p.16 FAQ Q9）＝オーバー回復してもそれ以上の意味はない（多く払い戻されない）
- ✅ 横向きのPPカードが0枚の状態でPP回復効果を使っても何も起こらない（p.16 FAQ Q9の実例）
- ⏳ PPの「持ち越し」＝ターンをまたいで余ったPPをそのまま次ターンに繰り越せるか、については明記が見当たらない。ただし終了フェイズで「余っているPP（縦向きのPPカード）と同じ枚数のカードをドローする」という処理があるため、実質的に「使わなかったPPはターン終了時にドロー数へ変換され消費される」＝翌ターンへPPそのものが持ち越されるわけではない、と解釈できる（開始フェイズで毎回「すべて回復」するため、そもそも「残す」という概念自体が発生しない）

### 公式根拠
- Playing Manual p.03, p.04, p.05, p.06, p.11, p.16 FAQ Q9

## 12. アタック解決順

これはゲームエンジンにとって最重要の項目のため、基本の手順（p.07）と詳細版（p.12）の両方を統合して整理する。

### 12-1. 基本の手順（p.07）

```
① コストと同じPPを支払う
↓
② カードを表向きにプレイエリアへ置く（同ターン中に複数プレイした場合は左から古い順に並ぶ）
↓
③ カードに「プレイ時」効果があれば、上から順に実行する
↓
④ 「アタックする」効果を実行する：アタッカーとなる自分のリーダーと、攻撃を受ける相手リーダーを選ぶ
↓
⑤ 攻撃を受けたリーダーにダメージを与える（ダメージカウンターを乗せる）
↓
⑥ 「アタック後」効果があれば実行する
```

### 12-2. 詳細版（p.12：複数カード・ダメージ計算・覚醒を含む完全版）

アタックカードをプレイしたとき、アタックカード自身とメモリア・タクティクスによる強化効果は以下の順で実行する。

```
① アタックカードの「プレイ時」効果を実行する
↓
② アタックカードの「アタックする」効果を実行する
    ↓ (2-1) アタッカーにする自分のリーダーと、攻撃を受ける対戦相手のリーダーを選ぶ
    ↓ (2-2) ダメージ値を計算する：
             このアタックを強化しているメモリア・タクティクスカードの「アタック強化」効果のダメージ
             + アタックカードのダメージ
             + アタッカーの攻撃力
             を合計する（条件付き・追加効果がある場合はここで確認・実行し、それも合算する）
    ↓ (2-3) ダメージを、アタックを受けたリーダーに与える（ダメージカウンターを乗せる）
↓
③ アタックカードの「アタック後」効果を実行する
    ※「アタック後」効果を持つアタックカード・メモリア・タクティクスカードが複数あるときは、ターンを行っているプレイヤーが実行順を自由に選べる
↓
④ 対戦相手のリーダーが1体以上ダウンし、アタッカーが覚醒していないなら、アタッカーを覚醒させ「覚醒時」効果を実行する
    ※体力以上のダメージカウンターが乗ったリーダーはすぐにダウンする
```

- ✅ 「アタック強化」効果（メモリア・タクティクス）は次に行う1回のアタックのみを強化する。強化効果を持つカードを複数連続でプレイした場合、それらは全てその次のひとつのアタックに合算適用される。ただし既に実行済みのアタックには遡って適用されない（p.09）
- ✅ 「アタック強化」または「アタックする」を実行する予定があるときは、メモリアカードをアタックカードより先にプレイする（p.09）。これは推奨の書き方（「〜しましょう」）だが、上記の「次に行うアタックのみ強化する」という仕組み上、アタック強化を効かせるにはアタックカードより前にメモリアをプレイする以外に方法がない
- ✅ 相手の最後のリーダーを倒した場合も、通常のダウン・覚醒と同様に処理し、「覚醒時」「アタック後」効果も実行する（p.15 FAQ Q4）

### 12-3. ラウンドがアタック処理の途中で終了した場合

- ✅ どちらかのプレイヤーのリーダーが全員ダウンした時点で、以下の順に処理してからラウンド終了処理（本書2章）へ進む（p.12）：
  1. その時点でプレイエリアにあるカードの効果のうち、まだ実行していないものをすべて実行する
  2. アタックや「アタック後」効果で対戦相手の最後のリーダーをダウンさせた場合、アタッカーが覚醒していないならアタッカーを覚醒させ「覚醒時」効果を実行する
  3. プレイエリアにまだ効果を実行していないカードがあれば、なくなるまで実行する
  4. ラウンドの終了処理へ（本書2章）
- ✅ 「ラウンドが終わるとき、まだ効果を実行していないプレイエリアにあるカードはどうするの？」→「効果を実行します。」（p.15 FAQ Q5）

### 12-4. 複数の「アタック後」効果の処理順（実例つき）

- ✅ 複数の「アタック後」効果がある場合、ターンを行っているプレイヤーが実行順を自由に選べる（p.12, p.15 FAQ Q6）
- ✅ 重要な注意点：実行順によって、後から実行する効果の「条件」の成立・不成立が変わりうる。例：メモリアカード「超新星」（アタック強化：次のアタックのダメージ+30／アタック後：このアタックを受けたリーダーがダウンしているなら、PPを2回復しカードを1枚引く）と、アタックカード「カウンタースナイプ」（アタックする：自分の手札が2枚以下なら、対戦相手の他のリーダー1体に20ダメージ）を手札2枚の状態で使う場合、「カウンタースナイプ」を先に実行すればその条件「手札2枚以下」を満たすが、「超新星」を先に実行して手札を1枚引いてしまうと「カウンタースナイプ」の条件を満たさなくなる（p.15 FAQ Q6）。＝**効果は宣言時ではなく実際に実行するタイミングで条件を再評価する**ことが示唆されている

### 12-5. 対象選択に関する確認済みルール

- ✅ 選べる対象がいない場合、効果は何も起こらない。例：対戦相手のダウンしていないリーダーが1体（＝アタック対象そのもの）しかいないとき、「対戦相手の他のリーダー1体に10ダメージ」＝attackした対象**以外**のリーダーを指す効果は、対象がいないため不発になる（p.16 FAQ Q8）

## 19. デッキ切れ（山札切れ）の処理

これは公式FAQ（p.14 Q1）に非常に詳しく記載されている。以下、処理を段階的に整理する。

- ✅ 前提：「カードを引く・デッキを見る・デッキを公開する」など、デッキのカードが必要になった場面で、デッキにカードがない場合に発生する
- ✅ 手順：
  1. トラッシュの裏向きのカードをすべてシャッフルしてデッキに戻す
  2. それでもカードが確保できない（＝トラッシュに裏向きのカードがない）場合、タクティクスデッキのカードをランダムに1枚選び、表向きにトラッシュへ置く（自分でランダムに選ぶ、またはシャッフルして裏向きのまま相手に選んでもらう、などの方法で1枚を選ぶ）
  3. 上記でカードを選ぼうとしたとき、タクティクスデッキに1枚もカードがなければ、**その試合に敗北する**
- ✅ 具体例（アタックカード「リンクアサルト」のアタック後効果：自分のデッキの上から3枚を見る。コスト1以下のメモリアカード1枚を、コストを支払わずにプレイしてもよい。残りはトラッシュに置く）を、デッキが1枚しかない状態でプレイした場合の処理順：
  1. カードを1枚裏向きのまま脇に避ける
  2. トラッシュの裏向きのカードをシャッフルしてデッキに戻す
  3. タクティクスデッキのカードをランダムに1枚選び、表向きにトラッシュへ置く
  4. デッキの上から2枚と、最初に避けた1枚を合わせて3枚を見る

- 🧩 上記から導かれるゲームエンジン設計：「デッキから引く／見る」処理は単純な配列操作ではなく、「不足時にトラッシュを再構築し、それでも不足ならタクティクスデッキを消費し、それも尽きたら敗北」という**フォールバック連鎖**を持つ関数として実装する必要がある

## 23. カード効果とルールの優先関係

- ✅ 「カードに、ルールと矛盾することが書いてある。」→「カードに書かれていることを優先してください。」（p.17 FAQ Q10）
- ✅ 具体例：通常ルールでは、ダウンしているリーダーをカード効果の対象にすることはできないが、タクティクスカード「復活ポータル」（プレイ時：ダウンしている自分のリーダー1体を、ダウンしていない状態に戻す。そのリーダーが装備しているカードすべてを表向きにトラッシュに置く。）は、その効果の対象にダウン中のリーダーを取ることができる（p.17 FAQ Q10）

## 24. FAQ 全文（p.14〜p.17、Q1〜Q14）

各FAQを「質問→公式回答→影響する基本ルール→ゲームエンジンへの影響」の形式で整理する。

### Q1（p.14）デッキのカードが足りないときはどうするの？
- 回答: 本書「19. デッキ切れ」参照（全文を転記済み）
- 影響する基本ルール: デッキ／トラッシュ／タクティクスデッキ／敗北条件
- ゲームエンジンへの影響: `drawCard()` 等のデッキ操作関数に、トラッシュ再構築→タクティクスデッキ消費→敗北、のフォールバック連鎖が必要

### Q2（p.14）「アタック後」効果で相手リーダーをダウンさせたとき、アタッカーは覚醒する？
- 回答: 覚醒する
- 影響: 覚醒トリガーは「アタックする」効果によるダウンだけでなく「アタック後」効果によるダウンも対象
- ゲームエンジンへの影響: 覚醒判定は「アタック処理全体（プレイ時〜アタック後まで）を通じて、対戦相手リーダーがダウンしたか」を見る必要がある（「アタックする」の瞬間だけを見てはいけない）

### Q3（p.14）「アタック後」効果で相手リーダーをダウンさせたとき、「このアタックを受けたリーダーがダウンしているなら」という条件は成立する？
- 回答: 成立しない（この条件は「アタックする」で攻撃を受けた本来のリーダーがダウンしているかどうかのみを見る）
- 影響: 効果の条件参照スコープ（「このアタックを受けたリーダー」＝アタック宣言時に選んだ対象1体を指す固定参照であり、後続の別効果でダウンした別リーダーを指さない）
- ゲームエンジンへの影響: Condition評価時に「アタック対象として記録した特定のリーダーID」を参照する仕組みが必要（動的に「今ダウンしている任意のリーダー」を見てはいけない）

### Q4（p.15）相手の最後のリーダーを倒したとき、アタッカーは覚醒する？「覚醒時」「アタック後」効果は実行される？
- 回答: 覚醒する。「覚醒時」「アタック後」効果も実行する
- ゲームエンジンへの影響: ラウンド終了（相手全滅）が確定した後も、未実行の効果解決を先に完了させてからラウンド終了処理に入る必要がある（本書12-3参照）

### Q5（p.15）ラウンドが終わるとき、まだ効果を実行していないプレイエリアのカードはどうする？
- 回答: 効果を実行する
- ゲームエンジンへの影響: ラウンド終了判定が成立しても、EffectStack/ResolutionStackが空になるまでラウンド終了処理を保留する必要がある

### Q6（p.15）「アタック後」効果が複数あるときの実行順は？
- 回答: ターンを行っているプレイヤーが自由に選べる。ただし実行順によって後続効果の条件成立が変わりうる（本書12-4に実例を転記済み）
- ゲームエンジンへの影響: ①複数の保留中「アタック後」効果をプレイヤーに選ばせるUI/API、②各効果の条件は宣言時ではなく実行時に評価、の両方が必要

### Q7（p.16）トラッシュのカードは見てもいい？
- 回答: 裏向き（アタック/メモリア）は自分も相手も見てはいけない。表向き（タクティクスの消費カード）は両者見てよい
- ゲームエンジンへの影響: トラッシュのGameState上の可視性はカード種別（表/裏の別）によって分岐する。オンライン対戦のマスク処理で重要

### Q8（p.16）対戦相手のダウンしていないリーダーが1体（＝アタック対象そのもの）しかいないとき、「対戦相手の他のリーダー1体に◯◯」はどうなる？
- 回答: 選べる対象がいないため何も起こらない
- ゲームエンジンへの影響: `target: "OPPONENT_OTHER_LEADER"`のような対象指定は、「アタック対象として選ばれたリーダーを除いた、ダウンしていないリーダー」の集合から選ぶ。集合が空なら効果はNo-opとして扱う（エラーにしない）

### Q9（p.16）回復とは何をすること？
- 回答: 体力の回復＝ダメージカウンター除去（乗っている分以上は回復しない）。PPの回復＝横向きPPカードを縦向きに（横向きが0枚なら何も起きない）
- ゲームエンジンへの影響: `heal()`/`recoverPP()`は、現在のダメージ量・横向きPP枚数を上限にクランプする実装にする

### Q10（p.17）カードにルールと矛盾することが書いてある場合は？
- 回答: カードの記載を優先する（本書23章に全文転記済み）
- ゲームエンジンへの影響: カード効果はルールエンジンの一般制約（対象選択条件等）を明示的にオーバーライドできる設計にする

### Q11（p.17）両プレイヤーが同時に試合の敗北条件を満たしたら？
- 回答: どちらも負けになる
- ⚠️ 前述の通り「試合の敗北条件」の粒度は要確認
- ゲームエンジンへの影響: 勝敗判定処理は「両者同時敗北→両者敗北（＝勝者なし）」の分岐を持つ必要がある

### Q12（p.17）プレイポイントカード等の実物がないと遊べない？
- 回答: 対戦相手の同意があれば代用可（デジタル実装では無関係。物理コンポーネントに関する注記）
- ゲームエンジンへの影響: なし（デジタル実装では常にGameStateとして管理するため該当しない）

### Q13（p.17）先攻プレイヤーは1ターン目の始めにカードを引く？
- 回答: 引く
- ゲームエンジンへの影響: 開始フェイズのドロー処理に、先攻1ターン目の特別扱いを実装してはいけない（例外なし）

### Q14（p.17）試合開始時のマリガンはある？
- 回答: ない
- ゲームエンジンへの影響: セットアップ処理に手札引き直しのステップを実装しない

## 26. カード効果システムの設計（引き続きドラフト。コードは未実装）

公式カードテキストの実例（本書やこれまでのExcel確認作業で見てきたもの：「プレイ時」「アタックする」「アタック後」「アタック強化」等）を踏まえ、以下の概念が必要と判断する。

- **Trigger（発生タイミング）**: `ON_PLAY`（プレイ時）／`ON_ATTACK`（アタックする）／`AFTER_ATTACK`（アタック後）／`ON_AWAKEN`（覚醒時）／`ATTACK_BOOST`（アタック強化、次の1回のアタックのみ対象）
  - 根拠：プレイングマニュアル中でカード効果ラベルとして実際に使われている「プレイ時」「アタックする」「アタック後」「アタック強化」「覚醒時」がそのままTriggerの分類に対応する（p.07, p.08, p.09, p.10, p.12）
- **Condition（条件）**: 「このアタックを受けたリーダーがダウンしているなら」「自分の手札が2枚以下なら」「プレイエリアにメモリアカードが2枚以上あるなら」等（FAQ Q3, Q6の実例より）。**条件は宣言時ではなく実行時に評価する**（本書12-4のFAQ Q6の実例より確認済み）
- **Target（対象）**: 「対戦相手の他のリーダー1体」「対戦相手のリーダーすべて」等。対象が存在しない場合はNo-op（FAQ Q8より確認済み）
- **Cost（コスト）**: PP。加えて「手札を1枚捨てることで」のような追加コストを伴う効果が存在することは、以前のカードテキスト確認作業で判明している（本マニュアルには一般ルールとしての言及はない）
- **Action（実行内容）**: DRAW/DAMAGE/HEAL/RECOVER_PP/DISCARD等
- **Modifier（数値修正）**: 「アタック強化」によるダメージ加算（本書12-2参照）
- **Duration（持続範囲）**: 「アタック強化」は次の1回のアタックのみ（p.09で明確に確認済み）。ターン中持続する効果があるかどうかは、今回のマニュアルには一般例が見当たらないため⏳
- **Replacement（置換効果）**: ルールを明示的に上書きする効果（例：復活ポータルがダウン中リーダーを対象にできる、FAQ Q10）。これは「ルールより優先される」効果として別扱いにする必要がある
- **Event（イベント）**: 覚醒・ダウン・アタック宣言・アタック解決・ラウンド終了など、他の効果のトリガーになりうる出来事

上記はいずれも実際にプレイングマニュアル本文中の処理・実例から抽出したものであり、本文に存在しない概念を追加してはいない。

## 27. カード効果の処理モデル（設計案。ルールそのものではない）

```
カードJSON（data/cards.json）
  ↓
効果定義（手動追加する effects: CardEffect[]。テキスト自動解析はしない）
  ↓

  ↓

  ↓

  ↓

  ↓
誘発効果の確認（新たにトリガーされる効果があればResolutionStackに積む）
  ↓
次の処理（プレイヤーが複数の保留効果から実行順を選べる場合はここで選択、FAQ Q6）
```

## 29. GameState（🧩実装上の仮仕様。公式ルールそのものではない）

公式ルールから実際に必要と判断できる状態を以下に整理する。

```text
GameState
├── matchId
├── matchMode: "STANDARD" | "QUICK"        // 22章参照。"STANDARD"という名称は仮称（"フルマッチ"という公式呼称は未確認）
├── roundNumber: 1 | 2 | 3
├── roundWins: { [playerId]: number }
├── turnPlayer: playerId
├── firstPlayerThisRound: playerId          // ラウンドごとの先攻（初回はジャンケン、以降は前ラウンド敗者）
├── phase: "START" | "MAIN" | "END"
├── isFirstTurnOfRoundForFirstPlayer: boolean   // 先攻1ターン目のタクティクス禁止判定に使用
├── players: {
│     [playerId]: {
│       deck: cardNumber[],              // 裏向き、順序を保持
│       hand: cardNumber[],              // 非公開
│       leaders: LeaderState[4],
│       tacticsDeck: cardNumber[],       // 裏向き、本人のみ閲覧可
│       tacticsArea: { cardNumber, faceUp: boolean }[],
│       playArea: { cardNumber, faceUp: true, effectsResolved: boolean }[],
│       trash: { cardNumber, faceUp: boolean }[],   // faceUp=trueはタクティクス（消費）のみ
│       ppCards: { max: number, used: number },     // 例: max=3/4/5、used分だけ横向き
│       hasPpTicket: boolean
│     }
│   }
├── effectStack / resolutionStack: PendingEffect[]
└── actionLog: GameEvent[]
```

```text
LeaderState
{
  cardId,          // カードマスタのcardNumber
  isDown: boolean,
  awakened: boolean,
  damage: number,  // ダメージカウンター数
  currentHp: number,   // = (awakened ? awakenHp : hp) - damage
  currentAtk: number,  // = awakened ? awakenAtk : atk
  equipment: cardId[]  // 装備タクティクスカード
}
```

- 🧩 手札・タクティクスデッキ・裏向きトラッシュは「非公開情報」のため、オンライン対戦を見据えて「全体GameState」と「プレイヤー視点でマスクしたGameState（相手の手札は枚数のみ）」を分離できる設計にする（FAQ Q7でトラッシュの裏/表による公開範囲の違いが明確に確認できているため、トラッシュも同様にマスク対象を分ける必要がある）

## ゲームエンジン実装前に確定必須の仕様

以下は、未確定のまま実装を始めると後から大きな手戻りが発生しうる項目。今回の公式マニュアル確認により、**ほとんどが確定した**。残るリスクは主に⚠️の2点。

- ✅ 確定：勝利条件・ラウンド条件・セットアップ・ターン順・フェイズ構成・PP・アタック解決順・ダメージ計算・ダウン処理・アタック後効果の処理順・手札上限・デッキ切れ・デッキ構築ルール
- ⚠️ 残課題1：「先攻1ターン目タクティクス禁止」が毎ラウンド適用されるか、試合最初のみか（本書15章）→ 未確定のまま実装すると、2ラウンド目以降のタクティクス解禁タイミングを誤る可能性がある
- ⚠️ 残課題2：FAQ Q11「試合の敗北条件」同時成立の粒度（本書1-2章）→ 未確定のまま実装すると、同時全滅のような特殊ケースでラウンド/マッチいずれの勝敗処理を呼ぶべきか誤る可能性がある
- ⏳ 覚醒の「再覚醒しない」ことの明文なし → 構造上の推論（🧩）で進めても実害は小さいと考えられるが、正式な明文確認が望ましい
- ⏳ 「フルマッチ」という名称自体は未確認 → 実装上の内部名称（`matchMode`等）はコード用の仮称として扱い、ユーザー向け表示文言を確定する際に公式名称を再確認する

上記以外は、今回確認した公式資料の範囲でゲームエンジン実装（GameState設計・PhaseEngine・AttackEngine・AwakenEngine等）に着手して問題ないレベルまで確定していると判断する。
