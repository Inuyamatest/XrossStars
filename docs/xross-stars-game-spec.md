# Xross Stars 対戦ゲーム仕様書（骨組み・公式情報待ち版）

このドキュメントは、実際に2人で対戦できるゲームエンジンを実装するための仕様を、公式情報の根拠とともに整理するためのものです。

**現時点ではまだゲームエンジンのコードは実装していません。** このファイルは「何が公式で確認できていて、何がまだ確認できていないか」を一覧化するための骨組みです。公式プレイングマニュアル（`https://xross-stars.com/rules` / 公式PDF）の内容を受け取り次第、各項目を確定させ、そのあとで初めて実装（`docs/xross-stars-game-spec.md` STEP 3以降）に進みます。

## この文書の読み方

各項目には、以下の3段階のいずれかのステータスを付けています。

| ステータス | 意味 |
|---|---|
| ✅ **公式で確認済み** | 公式サイトの個別カードページ・公式BANニュースなど、このプロジェクトが既に確認済みの一次情報から裏付けが取れているもの |
| ⏳ **公式情報が不足** | 公式プレイングマニュアル本文を未確認のため、まだルールを確定できないもの。**推測で埋めていません。** |
| 🧩 **実装上の仮仕様** | ルール自体は公式確認待みだが、実装の設計（データ構造・エンジンの形）としてはこの形にする、という技術的な決め事（ゲームルールの内容そのものではない） |

⏳ の項目は本文末尾の「公式情報待ちチェックリスト」にもまとめています。公式プレイングマニュアルの該当箇所を受け取り次第、この文書を更新し、ステータスを ✅ に変えてから実装に着手します。

**重要な前提**：前ターンでユーザーから提示された「現在確認できている公式の基本フロー」（セットアップ手順・ターン構造の概要）は、ユーザー自身が別環境で確認した情報として尊重しますが、私（Claude）自身はまだ公式マニュアル原文を直接確認できていないため、このドキュメント内では便宜的に「ユーザー提供の暫定情報」として ⏳ 扱いにしています。公式マニュアルの本文が提供され次第、そのテキストと突き合わせて ✅ に確定します。

## カード効果システムの設計（ドラフト・実装はまだしない）

ユーザー提示の型一覧をもとに、拡張可能な設計を先に整理する（600枚以上のカードを個別にハードコードしない方針）。

### 基本構造

```
CardEffect = {
  type: "DRAW" | "DAMAGE" | "HEAL" | "BUFF_ATK" | "BUFF_DAMAGE" | "REDUCE_DAMAGE"
     | "RECOVER_PP" | "DISCARD" | "DESTROY" | "REVEAL" | "PLAY" | "SEARCH"
     | "ADD_CARD" | "AWAKEN" | "EQUIP" | "ATTACK",
  amount?: number,
  target?: "SELF_LEADER" | "OPPONENT_LEADER" | "ALL_OPPONENT_LEADERS" | "SELF" | "ALLY" | ...,
  condition?: Condition,   // 「〜なら」を表す条件（下記）
  timing?: "ON_PLAY" | "ON_ATTACK" | "AFTER_ATTACK" | "ON_AWAKEN" | ...
}
```

- カードマスタ（`data/cards.json`）の各カードに、カードテキストとは別に `effects: CardEffect[]` フィールドを**手動で**追加していく方式にする（`js/data/effects.js` の `XS_EQUIPMENT` / `XS_PARSE_AWAKENING` に近い既存の考え方を踏襲・拡張）
- **カードテキストを自動解析してeffectsを生成することはしない**（ユーザーの指示通り）。効果が未定義のカードは「効果未実装」として扱い、テキスト表示のみ行う（ゲームが止まらないようにする）
- 既存の `js/data/effects.js`（`XS_EQUIPMENT`, `XS_PARSE_AWAKENING`）と役割が重複するため、ゲームエンジン実装時にこれらとの統合方法を検討する

### 条件（Condition）

「プレイエリアにメモリアカードが2枚以上あるなら」のような条件も、テキスト自動解析ではなく手動定義とする。

```
Condition = {
  type: "MEMORIA_COUNT_GTE" | "HAND_COUNT_LTE" | "LEADER_DOWN_COUNT_GTE" | "OVERKILL" | ...,
  value?: number
}
```

### 解決順（ResolutionStack）

- 「複数カードの効果を好きな順番で解決」「このアタックが終わってから」等のテキストに対応するため、効果を即座に適用せず `ResolutionStack` に積んでから順番に解決する設計にする
- 「好きな順番で」＝プレイヤーに選択させるUIが必要な効果は `requiresPlayerChoice: true` を持たせ、UIが介在するまでスタックの解決を一時停止できる構造にする
- この設計は技術アーキテクチャであり、公式ルール確認とは独立して先に固められる部分（🧩 実装上の仮仕様）

### BP05（先行公開）の扱い

- ステータス: 🧩 実装上の仮仕様
- `data/cards.json` に含めるが、`environment: "STANDARD" | "BP05_PREVIEW"` のようなフラグを持たせ、ゲーム開始時にどちらの環境で対戦するかを選べるようにする。通常環境のデフォルトにはBP05を混ぜない
