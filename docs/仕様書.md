# Xross Stars HP管理 仕様書

`index.html` の内容を解析して作成した仕様書です。
対象ファイル: `index.html`（約535KB、単一ファイルにすべてのアセットを同梱）

---

## 1. 概要

トレーディングカードゲーム「Xross Stars」の対戦時に、最大4人のリーダーのHP・ダメージ・覚醒・装備をスマホ／PCのブラウザで管理するツールです。

- 4つの「枠（スロット）」にリーダーを配置し、ダメージ／回復ボタンでHPを増減する
- 覚醒（HP・ATKの上昇）、装備（最大HPの変更）、任意値の増減、1手戻す、リセットに対応
- HPが0になった枠には「DOWN」オーバーレイを表示する
- サーバー通信なし。状態はページを開いている間のみメモリ上に保持（永続化なし）

## 2. 技術構成

### 2.0 ファイル構成（分割後）

2026-09-09 に、単一ファイルだった `index.html` を以下のように分割しました。元の単一ファイルは `index.bundled.html` として残しています。

```
index.html               ページ本体（<x-dc> テンプレート ＋ Component 登録の1行）
index.bundled.html       分割前のオリジナル（バックアップ。通常は使わない）
css/
  fonts.css              @font-face（Source Serif 4）
  broadsheet.css         デザインシステム "Broadsheet" のトークン・コンポーネント
  app.css                アプリ固有スタイル（html/body、フラッシュ等の keyframes）
js/
  app.js                 コンポーネントロジック（window.XSComponent = class extends DCLogic）
  storage.js             カスタマイズ内容の保存（IndexedDB）と画像縮小（window.XS_STORE / XS_COMPRESS_IMAGE）
  vendor/
    react.production.min.js       React 18.3.1
    react-dom.production.min.js   ReactDOM 18.3.1
    dc-runtime.js                 <x-dc> テンプレートを React で描画する独自ランタイム
    print-plates.js               Broadsheet の SVG フィルタ（本アプリではほぼ未使用）
  data/
    leaders.js           リーダー72名・色・弾（window.XS_LEADERS など）
    images.js            カード画像レジストリ（window.XS_LEADER_IMAGES など）
    effects.js           装備・効果データモデル（window.XS_EQUIPMENT など）
fonts/
  SourceSerif4-{Roman|Italic}-{subset}.woff2   12ファイル
docs/
  仕様書.md

```

**読み込み順の制約**

- React と ReactDOM を `dc-runtime.js` より先に読み込むこと。先に `window.React` があれば、ランタイムは CDN（unpkg）へ取りに行かずローカルのものを使う
- `js/app.js` は `dc-runtime.js` より後に読み込むこと（`window.DCLogic` を継承するため）
- `index.html` 末尾の `<script data-dc-script>` はインラインでなければならない（ランタイムが `textContent` を直接評価する仕様のため）。そこで `class Component extends XSComponent {}` の1行だけを書き、本体は `js/app.js` に置いている
- 横向きスマホ（ノッチ端末）対策として、左右にも `env(safe-area-inset-left/right)` の余白を取る
- `file://` で直接開いても動作する（外部通信なし）。ブラウザ側の制限で不都合があれば、任意の静的サーバーで配信する

### 2.1 旧ファイル構造（`index.bundled.html`、バンドル形式）

分割前の `index.bundled.html` は「バンドラー」形式で、1ファイルに以下を内包しています。

| セクション | 内容 |
|---|---|
| 起動前の見た目 | ダーク背景に「HP / Xross Stars」のサムネイルSVGと「Unpacking...」表示 |
| ローダースクリプト | manifest 内の base64 アセットを展開し、template を実DOMに差し替える |
| `__bundler/manifest` | アセット19件（JS 7件、woff2フォント12件）。JSはgzip圧縮＋base64 |
| `__bundler/ext_resources` | 外部URL→UUIDの対応（React 18.3.1 / ReactDOM 18.3.1 のUMD） |
| `__bundler/page_order` | 空配列（ネストページなし） |
| `__bundler/template` | 実際のページHTML（JSON文字列として格納） |

起動時の流れ:

1. `DOMContentLoaded` で manifest の各アセットを展開し Blob URL を生成する
2. template 内のUUIDをBlob URLに置換し、`DOMParser` で解析して `document.documentElement` を差し替える
3. `<script>` を再生成して順番に実行する（React → ReactDOM → DCランタイム → データスクリプト）

### 2.2 同梱されるスクリプト

| アセット | 役割 |
|---|---|
| React 18.3.1 / ReactDOM 18.3.1 | UI描画エンジン |
| dc-runtime（約69KB） | `<x-dc>` テンプレート（`sc-for` / `sc-if` / `{{ }}`）を React に変換して描画する独自ランタイム。`DCLogic` 基底クラスを提供 |
| Broadsheet print-plates.js | デザインシステムのSVGフィルタ（CMYK版ずれ表現）。本アプリでは `.halftone` 以外は未使用 |
| リーダーデータ | `window.XS_LEADERS` 等を定義（後述） |
| 画像レジストリ | `window.XS_LEADER_IMAGES` 等を定義（後述） |
| 効果データモデル | `window.XS_EQUIPMENT` 等を定義（後述） |

### 2.3 フォント

Source Serif 4（400 / 600、通常・イタリック、各言語サブセット）を woff2 として `fonts/` に同梱。見出し・本文ともにこのフォントを使用します。400 と 600 は同じ可変フォントファイルを共有しています。

### 2.4 外部依存・注意点

- ネットワークアクセスは不要。オフラインで動作する
- **カード画像は同梱されていない。** 画像パスはすべて `cards/xxx.webp` の相対パスのため、`index.html` と同じ階層に `cards/` フォルダを配置する必要がある。存在しない場合はリーダー名の頭文字だけが表示される
- JavaScript 無効時は「This page requires JavaScript to display.」と表示される

## 3. 画面仕様

配色はダークテーマ固定（背景 `#201e1d`、パネル `#2d2b2b`、文字 `#f3f2f2`）。
回復系は青（`#62c5ee` 系）、ダメージ系はピンク（`#ff458e` 系）で統一。

### 3.1 メイン画面

```

│ XROSS STARS  HP管理   − 回復 ＋ ダメージ [全員HPリセット] │  ← ヘッダー
├──────────────────────┬──────────────────────┤
│ リーダー枠 1          │ リーダー枠 2          │
├──────────────────────┼──────────────────────┤
│ リーダー枠 3          │ リーダー枠 4          │
└──────────────────────┴──────────────────────┘
```

**グリッド列数**（`layout` プロパティ、既定 `auto`）

| layout | 列数 |
|---|---|
| `auto` | 画面幅 620px 以上で4列、未満で2列（リサイズで自動切替） |
| `2x2` | 常に2列 |
| `1x4` | 常に4列 |

枠内の操作ボタンは列数にかかわらず「−10」「＋10」の2つ（2列×1行）です。

### 3.2 リーダー枠（空き状態）

- 破線枠のボタン「＋ リーダー N / リーダーを選択」
- タップでリーダー選択画面（3.3）を開く

### 3.3 リーダー枠（配置済み）

上から順に:

1. **カラーバー**（高さ4px）: リーダーの色（赤／青／緑／黄）
2. **名前行**: リーダー名、覚醒中は「覚醒」バッジ、右端に「⋯」メニューボタン（→ 3.5 カードメニュー）
3. **装備行**（装備がある場合のみ）: 「【装備】名前・名前」
4. **カード画像**: `<img>` で描画し、切り抜きなしで全体を表示（`object-fit: contain`）。ハーフトーン加工あり。タップで詳細ダイアログ（3.4）。画像がない場合は名前の頭文字を表示
5. **数値表示**
   - 左: `HP` 現在HP（28px、画面高さ 520px 以下では 22px）`/ 最大HP`
   - 右: `DMG ／ ATK` 累計ダメージ（ピンク）と攻撃力
6. **操作ボタン**（2個）: `−10`（回復・青） / `＋10`（ダメージ・ピンク）

**HPダウン表示**: 現在HPが0になると枠全体にピンクの枠線と半透明の幕、中央に「DOWN」を表示（操作ボタンはそのまま押せる）。

**フラッシュ演出**（`showFlash` プロパティ、既定 `true`）: ダメージ時はHP数値がピンクに、回復時は青に一瞬拡大するアニメーションを表示。

### 3.4 リーダー選択画面（フルスクリーン）

- タイトル「リーダー N を選択」と閉じるボタン
- **検索ボックス**: リーダー名の部分一致（大文字小文字無視）
- **弾フィルター**: 「すべて」＋収録弾ボタン（第1弾〜第4弾。データから自動生成）
- **色フィルター**: 「すべての色」＋赤／青／緑／黄
- **件数表示**: 「登録 72名（第1弾 24名 / 第2弾 16名 / 第3弾 16名 / 第4弾 16名）」
- **結果リスト**: 各行に色バー、名前、収録情報（弾『弾名』・カード番号）、`HP 100 → 130`、`ATK 30 → 40`
  - 他の枠で使用中の同名リーダーは半透明＋選択不可
  - 該当なしの場合「該当するリーダーがいません。」
- 選択すると枠に配置され、HP は満タン・ダメージ0・未覚醒・装備なしで初期化される
- 検索語は開くたびにリセットされるが、弾・色フィルターは保持される

### 3.4.1 リーダーのカスタマイズ（選択画面の ⚙）

選択画面のタイトル右にある「⚙」ボタンでカスタマイズモードを切り替えます（ON の間は青く点灯）。

- ON にすると、各リーダー行の右側に「⚙」ボタンが現れ、案内文「カスタマイズ中：…」を表示する
- 行の「⚙」をタップすると、そのリーダーの**カスタマイズ編集ダイアログ**（z-index 42）が開く
- カスタマイズ済みのリーダーは、行の収録情報の末尾に「・ カスタム」と表示される

**編集ダイアログの項目**

| 項目 | 内容 |
|---|---|
| 名前 | テキスト。空欄で保存すると元の名前のまま |
| 覚醒効果テキスト | 複数行テキスト |
| HP（覚醒前／覚醒後）、ATK（覚醒前／覚醒後） | 数値。空欄や数値でない場合は元の値のまま |
| 画像（通常）／画像（覚醒後） | 「画像を選ぶ」で端末の画像を選択。`<img>` で全体プレビュー。カスタム画像があれば「元の画像に戻す」が出る |
| 保存 | 元データと異なる項目だけを上書き設定として保存し、ダイアログを閉じる |
| 初期設定に戻す | このリーダーの上書き設定をすべて削除（カスタマイズ済みのときのみ表示） |
| キャンセル | 変更を破棄して閉じる |

**保存の仕様**

- 保存先はこの端末のブラウザ内 IndexedDB（DB `xs-hp`、ストア `leaderOverrides`、キーはリーダーID）。他の端末・ブラウザには同期されない
- 画像は保存前に長辺 900px 以内へ縮小し、JPEG（品質 0.86）の data URL として保存する
- 画像はすべて `<img>` 要素で描画する（CSS の background-image では長い data URL が途中で切れて表示されない問題があったため）
- 起動時にすべての上書き設定を読み込み、元データに重ねたものをカタログとして使う（`catalog()`）。名前・画像・数値はすべての画面（選択リスト、枠、詳細ダイアログ）に反映される
- 保存時に、その リーダーを配置中の枠にも新しい名前・画像を即時反映する。ただし HP・ATK の数値は次に操作した時点（または配置し直し）から反映される
- 元データそのもの（`js/data/*.js`）は書き換えない

## 4. 状態とロジック

### 4.1 スロットの状態

| フィールド | 説明 |
|---|---|
| `card` | 配置中のリーダーデータ（null なら空き） |
| `baseMaxHp` | 基本の体力（覚醒・装備で導出） |
| `manualMaxDelta` | 「最大HP ±10」の累積値 |
| `maxHp` | 最大HP（導出値） |
| `damage` | 累計ダメージ（0 〜 maxHp） |
| `currentHp` | `maxHp − damage`（0以上） |
| `isDown` | `currentHp <= 0` |
| `awakened` | 覚醒中か |
| `attack` | 現在の攻撃力 |
| `equipment` | 装備配列 |
| `history` | 直近30件の操作スナップショット（1手戻す用） |
| `lastLabel` | 直前の操作ラベル |

### 4.2 最大HPの計算式

```
基本の体力 = 覚醒中 ? card.awakenedHp : card.hp
            （SET_BASE_HP 効果の装備があれば、その normal / awakened で上書き）

最大HP = max(0, 基本の体力 + Σ MAX_HP_MODIFIER.amount + manualMaxDelta)
```

- 累計ダメージは `0 〜 最大HP` に丸められる（最大HPが下がるとダメージも切り詰められる）
- 現在HP = `max(0, 最大HP − 累計ダメージ)`
- **HPは「累計ダメージ」で管理**しているため、覚醒や装備で最大HPが増えると現在HPも同じだけ増える

### 4.3 操作一覧

| 操作 | 処理 | 履歴ラベル |
|---|---|---|
| −10 / 回復（任意） | damage を減らす | 「N回復」 |
| ＋10 / ダメージ（任意） | damage を増やす | 「Nダメージ」 |
| 最大HP ±10 | manualMaxDelta ±10 | 「最大HP +10」 |
| 覚醒する | awakened=true、attack=awakenedAttack | 「覚醒」 |
| 覚醒を解除 | awakened=false、attack=attack | 「覚醒解除」 |
| 装備を追加 | equipment に追加（同一IDは不可） | 「〇〇 を装備」 |
| 装備を外す | equipment から削除 | 「〇〇 を外す」 |
| 1手戻す | history 末尾の状態を復元（最大30手） | 復元前のラベル |
| HPをリセット | 累計ダメージを0にして最大HPまで全回復。覚醒状態・装備・最大HP調整はそのまま（確認あり、1手戻すで取消可） | 「HPリセット」 |
| リーダーを外す | 枠を空きに戻す（確認なし） | ― |
| 全員HPリセット | 全枠のHPをリセット（確認あり） | 「HPリセット」 |

任意の値の入力は絶対値の整数として扱い、数値でなければ 0 とみなします。

### 4.4 コンポーネントプロパティ

| プロパティ | 型 | 既定 | 説明 |
|---|---|---|---|
| `layout` | `auto` / `2x2` / `1x4` | `auto` | グリッド列数 |
| `showFlash` | boolean | `true` | HP数値のフラッシュ演出 |

## 5. データ仕様

### 5.1 リーダーデータ（`window.XS_LEADERS`）

出典: https://xross-stars.com/card（dataVersion 1.0.0）

登録数: **72名**（第1弾 24名 / 第2弾 16名 / 第3弾 16名 / 第4弾 16名、色は各18名）
※ スクリプト冒頭のコメントには「64名」と記載があるが、実データは72名。

| 弾 | 弾名 |
|---|---|
| 第1弾 | Luminous Daybreak |
| 第2弾 | Exceed Rampage |
| 第3弾 | Broken Neonlights |
| 第4弾 | Grand Resonance |

レコード形式:

```json
{
  "id": "BP01-001",
  "name": "うるか",
  "booster": "第1弾",
  "boosterName": "Luminous Daybreak",
  "cardNumber": "BP01-001/100",
  "color": "red",
  "hp": 100,
  "awakenedHp": 130,
  "attack": 30,
  "awakenedAttack": 40,
  "awakeningEffect": "対戦相手のリーダーすべてに10ダメージ。",
  "officialCardUrl": "https://xross-stars.com/card/1-001"
}
```

- HP は 100 または 110、覚醒後は +30。ATK は全員 30 → 40
- `hp` が未設定の場合は `XS_DEFAULT_HP`（100）を使用
- 同一リーダーのパラレルレアリティ（LRP/LRPP）は重複登録しない
- 第5弾以降は `leaders` 配列に追記するだけで、弾フィルター・件数表示に自動反映される

読み込み完了時に `xs-leaders-ready` イベントを発火し、アプリがスロットを再初期化します。

### 5.2 色定義（`window.XS_COLORS`）

| key | 表示 | hex |
|---|---|---|
| red | 赤 | `#ff458e` |
| blue | 青 | `#62c5ee` |
| green | 緑 | `#6fae7c` |
| yellow | 黄 | `#edbb00` |

### 5.3 画像レジストリ（`window.XS_LEADER_IMAGES` / `XS_LEADER_IMAGES_AWAKENED`）

- キーはリーダー名、値は `cards/` 配下の相対パス（webp、一部 png）
- 通常画像: 72名分すべて登録済み
- 覚醒後画像: 18名分登録。未登録の場合は通常画像を使用
- 解決順: `card.awakenedImageUrl` → 覚醒レジストリ → `card.imageUrl` → 通常レジストリ
- `window.XS_VERIFY_IMAGES()` を起動時に呼び、画像の登録状況をコンソールに出力する

### 5.4 効果データモデル（`window.XS_EQUIPMENT` ほか）

```
Effect =
  | { type:'DAMAGE',          amount, target:'SELF'|'OPPONENT'|'ALL_OPPONENTS' }
  | { type:'HEAL',            amount, target:'SELF'|'ALLY' }
  | { type:'MAX_HP_MODIFIER', amount, target:'SELF'|'ALLY' }   // 最大HPを増減
  | { type:'SET_BASE_HP',     normal, awakened }              // 基本の体力を上書き
  | { type:'EQUIP',           cardId }
```

アプリが実際に処理するのは `MAX_HP_MODIFIER` と `SET_BASE_HP` の2種類です。

登録済み装備:

| id | 名前 | 効果 |
|---|---|---|
| BP03-080 | サイバネアーマー | 基本の体力を 未覚醒 140 / 覚醒 170 に上書き |

その他、`XS_TACTICS`（応急処置: 味方1体を20回復）と `XS_PARSE_AWAKENING`（覚醒効果テキストから HEAL/DAMAGE を抽出する関数）が定義されていますが、現在のUIからは使用されていません。

## 6. 既知の制約・補足

- 対戦中のHP・ダメージ等の状態はページリロードで消える（保存されるのはリーダーのカスタマイズ内容のみ）
- 「リーダーを外す」は確認なしで即実行される
- 「1手戻す」は装備・覚醒・最大HP変更・HPリセットを含むすべての操作を対象とする
- 同名リーダーは4枠で1人までしか配置できない
- カード画像フォルダ `cards/` が別途必要（2.4 参照）
